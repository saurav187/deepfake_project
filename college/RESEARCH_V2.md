# A second release for Hindi and English voice recordings

Research date **23 November 2026**. Repository reference **detector-v2 at a90fa8e**. Start with **35.41 GB** of new development data and the existing frozen XLS-R 300M. The first question is whether matched modern synthesis raises recall on a withheld generator family at a tolerable false-alarm rate on genuine phone speech. A new encoder can wait until that experiment establishes a baseline. All performance targets and GPU budgets below are proposals. There are no measured v2 accuracy or latency results.

From the repo root on Linux, set the path to the **mounted HDD**. Run only the commands for the group you want.

```bash

findmnt -T "$DATA"

college/DOWNLOAD_PLAN.sh "$DATA" shrutilipi speechfake
```

Watch progress in a second terminal with `college/DOWNLOAD_STATUS.py "$DATA"`. Add `--once` for one snapshot or `--interval 10` for a ten-second refresh. The monitor estimates partial bytes from disk allocation and uses the published transfer totals above.

The directory must exist. A declined prompt or EOF skips that dataset. Rerun the same keys on interruption. The script needs Python 3.11+, huggingface_hub (available in the project environment) and curl. It keeps Hub payload caches on the target drive by default. If cache variables are already set, point them to the HDD first. Restricted cards need access for the account supplying the token. Deepfake-Eval needs a research application. Use the publisher card to retain the licence/notice with the research inventory. Keep the private credential outside dataset manifests. The sealed directory should be readable by the evaluator only when practical; configure development loaders with an explicit allowlist under `development/`.

## What v1 actually does

The reference is the three-head release in [RESULTS.md](../detector/RESULTS.md). On development, frozen XLS-R achieved mean EER 5.1% against 8.1% for WavLM Base+ in a one-seed limited-data comparison. IndieFake dev has **four speakers**. More windows from those people do little to measure false accusations against a new speaker. Historical ITW AUC 0.957/EER 11.3% and VA 19/22 fake detections are context for v1 only. The owner's separate report of recent TTS passing supplies a hypothesis for fresh development recordings.

- `data/sources.py` already uses verified ASVspoof split tars by byte offset. `build_manifest.py`, `audit.py` and `edge_probe.py` provide decoder/PCM hashes, speaker roles, format controls and an edge-feature gate. Preserve these, with train/dev-only inputs to v2 design jobs. Source-prefixed speaker IDs cannot by themselves detect the same reader in another corpus.
- `audio.prepare_with_offset` removes at most 0.25 s per edge, capped at 10% of the trimmed clip per side. Energy bounds include internal pauses, music and noise. `inference.py` uses prepared span as speech duration and tiles short audio. Timeline offsets already account for trimming. Explore a voiced-frame count and keep timestamps in original coordinates.
- `train/data.py`'s default dev iterator caps coverage at four windows, while inference scores all windows; `train.score_dev` instantiates that capped default. Evenly spaced windows can overlap at the tail. Use one policy for training evaluation, calibration and serving and weight by newly covered speech. The current dev codec transformation already precedes trimming, and failed train loads are masked from loss in `train/train.py`. Dev EER can silently average fewer source cells when nonfinite scores or missing classes remove a cell.
- `augment.py` includes single codecs, noise, gain and edges; fitting to a single synthetic channel is a weak substitute for actual forwards. `model/ssl.py` freezes all encoder parameters, runs them under no-grad, forces encoder eval and excludes encoder weights from saved trainable state. Each assumption matters for adaptation. `calibrate.py` reuses selection predictions, fits a source-balanced sigmoid and derives both cutoffs on the same dev scores. Its 0.514–0.562 band describes that mixture. `eval/evaluate.py` already supports frozen releases, logging and speaker resampling. Extend the ledger to new sets and keep per-item diagnostics with the custodian.

## Buildable v2 design

### 1. Form paired examples before assigning splits

A development record needs a stable row ID, dataset/revision, original and reference recording IDs, speaker and donor, language, generator family/checkpoint/service date, transcript or prompt-family hash, original channel, processing history, label and role. Keep licence and consent IDs in the collection inventory. Hash exact decoded PCM and fingerprint near-duplicates for crop/re-encode matches. Group all versions of a parent together. For Libri-derived data include reader and book IDs; for interviews use source-video and person IDs. Quarantine unknown or conflicting joins. If donor relationships create one giant connected component, discard bridging examples or dedicate that component to one split. Report rows and independent speakers lost.

Keep official train/dev boundaries. From development-eligible speakers form disjoint train, model-selection, Platt-fit, threshold-fit and final **development verification** cohorts. Target 60/15/10/10/5 by group as a starting allocation; sample size by language/class governs feasibility. Reserve a generator family and every related version from fitting, expose a separate family in selection, and keep a further family blind until verification. Use nested grouped cross-validation on limited development sources for exploratory comparisons. Do not imply a validated Hindi threshold if independent speakers run out. In particular, splitting four IndieFake dev speakers five ways cannot support this design. Recruit additional people and borrow only a prespecified pooled cutoff while a stratum is unsupported.

Start with 20–40k eligible paired recordings across sources if the joins support it. Cap repeated variants at four per original per epoch. Draw language, paired source domain, label, generator (for fakes) and parent in turn. Give comparable mass to Hindi and English for the target pilot, 50/50 real/fake within each supported source-language-channel. A paired source domain means, for example, Kathbath originals **and their matched** IndicSynth outputs. Treating the two repositories as independent single-label sources defeats the existing sampler. Cap celebrity/audiobook influence. Include code-switching as its own measured slice. Log effective number of speakers, families, examples and hours seen, with replacement rates. Use unmatched genuine recordings in an explicit genuine-only challenge for false alarms. Add them to gradient updates only after matched synthetic controls exist.

For the matched phone pilot, recruit 20–30 consenting development speakers across Hindi and Indian English, two sessions per person, two device types where possible. Use self-written everyday sentences, questions, numbers, names and pauses plus a spontaneous response; hold out entire prompt templates. Capture genuine and synthetic playback over the same transfer paths in randomized order. Include room speech, quiet direct send, forwarded audio, genuine edits and background music. Preserve one parent ID across all versions. Target 5–10 h each of genuine and generated speech initially, then 20–40 h only if held-out gains continue. Keep the separate owner test speakers out from day one.

Self-generation pilot: Kokoro-82M English stock voices and Chatterbox multilingual Hindi/English on explicitly consented voices, initially 2–5 h per tool, batch one, short utterances. Match narrator mix across labels. For stock voices with no corresponding genuine talker use only the domain-matched auxiliary arm and report it separately. Add an independent VC family to development if rights and source permissions are cleared. Reserve one entire family, e.g. F5-TTS, for an independently acquired development verification set; never use its artifacts in training, including derivative versions. Track whether a family actually occurs in existing corpora. Assign OpenAI/Gemini/ElevenLabs service outputs by dated model ID and vendor; unknown checkpoint stays unknown. Use owner-authorized outputs for private tests only where service terms permit. ModelScope covers earlier GPT-SoVITS, Fish, OpenVoice and Seed-VC; evidence for transfer to CosyVoice 2/3, Qwen3-TTS, VibeVoice, RVC and newer services must come from separate family/version rows. Unsupported products get “unmeasured”. On 8 GB time a ten-utterance generation pilot including peak VRAM and real-time factor before budgeting. Use a separate compatible generator environment on HDD; keep detector Python 3.14 and its pinned packages intact. [Kokoro weights, Apache 2.0](https://huggingface.co/hexgrad/Kokoro-82M) · [Chatterbox weights, MIT](https://huggingface.co/ResembleAI/chatterbox)

On the HDD, join metadata in one sequential pass, then write native compressed audio with small metadata records to 256–512 MB uncompressed tar shards with an offset index. Partition by role before packing. Mix parents from several balanced cells in each train shard, shuffle shard order and use a bounded in-memory shuffle buffer. Start with two workers and prefetch one; measure samples/s, GPU utilization and decoder wait against four workers. Keep original Parquet row groups where sequential batches suffice. Pin file lists, checksums and training seeds; avoid thousands of random small reads or terabytes of frame embeddings. Dataset packing is offline, on licensed research recordings.

### 2. Compare the cheapest plausible model changes

| Candidate | What it might fix and how to decide |
|---|---|
| Frozen XLS-R 300M, existing layer mix + attentive statistics + MLP | First run on every new recipe. Local dev supports it and three heads can share one encoder pass. Train balanced BCE and save per-window logits; confirm that gains survive a common low-false-alarm operating point. |
| Rank-8 LoRA on query/value projections of top four blocks; alternatively unfreeze top two blocks | More capacity for fine acoustic cues at modest trainable-state size. Start head LR 3e-4, adapter LR 1e-4 or unfrozen-block LR 1e-5; pilot values. Keep frozen lower layers outside autograd and enable gradients for adapted upper blocks. Check nonzero parameter updates and export/reload parity. Include adapter weights in release hash. Separate fine-tuned encoders per ensemble seed multiply deployment cost; select one encoder and fit multiple cheap heads if warranted. |
| WavLM Base+ / Large, w2v-BERT 2.0, MMS, XLS-R 1B/2B | WavLM Base+ is an existing smaller CPU comparator. WavLM Large offers speaker/acoustic representations; w2v-BERT offers multilingual acoustic features and a different input pipeline. MMS is a multilingual challenger with NC weights. 1B/2B in bf16 need roughly 2/4 GB for weights alone, before activations, gradients and optimizer. A frozen single-window probe may fit 8 GB. Full AdamW tuning and a 2 GB laptop bundle are poor fits. Try one challenger only if smaller variants plateau; profile real peak memory. Published numbers give scale, not a ranking for this app. Garg et al. report **5.70% ITW EER** with an ensemble of five four-speaker HiFi-GAN-trained detectors; this is evidence against assuming more generator names always improves transfer. ### 3. Training, duration and channel controls

Use bf16 autocast if a forward/backward smoke test passes, float32 loss/pooling accumulators, 4 s windows, microbatch 2–4 and gradient accumulation to effective batch 32. Checkpoint *trainable* transformer blocks if needed. Clip gradient norm at 1, log peak allocated/reserved VRAM and time for 100 measured steps after warm-up. Keep optimizer updates and unique parents comparable across arms. Start from one seed; repeat a promising result on two further seeds. BCE is the baseline. OC-softmax is a controlled test of genuine-class compactness on diverse genuine speech. Focal loss can overemphasize mislabeled or unmatched hard negatives. SAM/ASAM require a second gradient evaluation per update; defer until a matched-time comparison is affordable. Mixup on waveform mixtures creates overlapping voices with ambiguous file labels; first use annotated splices and same-label mixtures as controls.

Start with equal-label paired channels: 50% clean, 35% one MP3/AAC/Opus or narrowband phone codec, 15% tandem transcode or playback/recapture (trial proportions). Apply to full recordings before shared preparation. Compare Opus at 16 kb/s with clean and MP3 32 kb/s; **bitrate is distinct from sample rate**. Pair 8 kHz band-limiting, device capture, noise, clipping, mild room reverb and gain across labels. Use recordings from devices/rooms omitted from augmentation as development checks. RawBoost's nonlinear filtering/impulses are a separate experiment with clean controls. Augmentations that increase genuine false alarms or erase splice recall leave the recipe. Use a clean first epoch then mixed channels as a tested curriculum, with identical total updates to the fixed-mixture arm.

For short clips compare true-length 0.75/1/2/4 s crops with tiling at equal parent counts. Propagate valid-frame masks through normalization, encoder attention and pooling. Use a lightweight speech activity model, checked against hand-marked speech/non-speech on Hindi/English phone development audio. Test internal pauses, music, isolated consonants and low-energy real voices. Keep original timestamps, symmetric fades and a development edge-probe gate. Only lower the current minimum from 1.0 to 0.75 s if new eligible samples meet the false-accusation budget and give materially better correct determinate coverage. Otherwise keep the minimum and show the four standard verdicts. Severe uncertainty on intelligible speech and too little detectable speech are distinct app outcomes.

Start aggregation with mean logits; account for tail overlap by duration of unique speech. Compare one 4 s window per ~4 s with a 2 s hop, and test a contiguous high-evidence region for partial fakes against genuine edits. A max over many windows increases long-file false alarms. Require event recall at fixed false regions per genuine hour and evaluate by insertion duration. A colored timeline conveys relative evidence; file-level calibration cannot supply calibrated probabilities for individual windows. Keep the PRD §7 fields and disclose reference prior and segment meaning. Measure localization on annotated development splices before claiming it works on clips with mixed authenticity.

### 4. Error budgets, thresholds and the final evaluation

Select architecture on macro held-out-family recall at a common 2% genuine false-alarm target on **selection** data with channel/length/language coverage and counts. Estimate selection operating points in grouped folds. Predeclare the following provisional product budgets: false accusation ≤2% of all genuine recordings, false reassurance ≤5% of all synthetic recordings, determinate coverage ≥60% per supported language. Report the same errors among determinate cases and all four outcomes separately so abstention or refusal cannot manufacture success.

Fit a global monotone Platt map on the disjoint Platt cohort using recording logits, balanced genuine/fake weighting within language and paired source, one total vote per parent across channel views. Label the displayed score as calibrated for a reference population with 50% fake prevalence. On the threshold cohort choose `t_fake` from the upper genuine-score tail and `t_real` from the lower fake-score tail. Search ordered pairs with `t_real < t_fake`, maximizing correct determinate coverage subject to both error limits. For 0.75–<1, 1–<2, 2–<4 and ≥4 s voiced-duration bins, use pooled estimates when support is thin; pilot monotonic constraints letting shorter clips abstain more. Implement all-uncertain/unsupported as explicit states if no feasible pair exists; widening a band by an arbitrary percentage has no risk interpretation. Verify frozen choices against one-sided 95% bounds on independent verification speakers. One successful call per each of 149 independent genuine speakers with zero false alarms gives an exact upper bound of about 2%; repeated views of five speakers cannot substitute. If insufficient, label subgroup performance exploratory and recruit more independent controls. Report Brier score, log loss, reliability bins with counts and risk vs coverage curves.

For each sealed source, freeze model, processing, eligibility, bins, operating points, versions and protocol hash before scoring, and log one run per release. A custodian checks parent fingerprints and identity overlaps with a blinded index, then applies prespecified exclusion/reporting rules. Development tools must never enumerate sealed rows or read sealed labels. Report file-level ROC AUC and EER on scoreable items, TPR at frozen operating point, raw class counts including insufficient and decode failures, confusion by language, amount of speech, codec, device, vendor and generation family. Label exact checkpoint seen, related family seen, documented unseen and unknown separately. Family-macro and worst-supported results accompany pooled metrics. Report uncertainty/insufficient separately. Use paired speaker-cluster bootstrap (e.g. 2,000 resamples, 95% intervals), keeping all parent variants and sessions together; use source event or parent clusters if speaker unavailable and state the limitation. Publish denominators for non-estimable slices. On the private 50+50 set even 0/50 false alarms leaves a one-sided 95% upper bound ~5.8% under independence. Use it as a fresh confirmation, not a public 2% guarantee. A redesign after seeing sealed outcomes needs fresh confirmation material.

### 5. Serving and deployment

Use the same prepared waveform, voiced mask, window schedule and encoder/head combination offline and via FastAPI. Exercise `/api/analyze` with licensed fixtures. Bound CPU batch size and worker/thread concurrency. Keep analysis in memory; do not log or persist uploads. Benchmark actual laptop on battery and AC, with cold start and warm p50/p95 for 3/10/30 s recordings, mono/stereo MP3/AAC/Opus and 1/2 concurrent clients. Measure elapsed receive-to-response, resident memory and peak decode time. Proposed gate: warm single-request p95 ≤5 s/30 s and total distributable weights ≤2 GB. V1’s desktop ~3 s/28 s is only a reference. A single fp32 300M encoder is ~1.2 GB before overhead.

Try dynamic int8 linear layers on CPU or ONNX Runtime as a separate calibrated candidate; measure genuine-tail drift and score/verdict parity by duration/channel, not just average logit similarity. Calibrate after quantization and re-freeze. If still slow, distill training-only teacher logits into a 30–80M parameter small speech model, train jointly with BCE, retain bands and benchmark on development phones. A 60M int8 model has ~60 MB raw weights; 150 MB must cover the packaged runtime and frontend too. Compare end-to-end quality, memory, battery and wait time. If the student fails, keep computation server-side for mobile. No sealed labels enter quantization or distillation.
